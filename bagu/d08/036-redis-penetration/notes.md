# 36. 穿透、击穿、雪崩 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **缓存失效时流量打到 DB** 的三种病，必须分开讲。

| | 现象 | 根因 |
|--|------|------|
| **穿透** | 查不存在的数据，缓存没有也没有空值 | 请求绕过缓存打 DB，常被乱 ID 扫 |
| **击穿** | 一个 **热点 key** 过期 | 瞬间所有请求打同一行 DB |
| **雪崩** | **大量 key** 同时过期或 Redis 挂 | DB 被打满 |

## 2. 核心机制与对策

**穿透**

- 缓存空值（短 TTL）。
- 布隆/布谷过滤器挡确定不存在的 id（题 37）。
- 参数校验、网关限流。

**击穿**

- 热点永不过期，逻辑过期后台刷新。
- 单 key 互斥锁：只有一个请求回源，其他人等或稍后再读缓存。
- 提前续期、随机抖动不够，因为是 **一个** key。

**雪崩**

- TTL 加随机，避免整点一起死。
- Redis 高可用（哨兵/集群），多副本。
- 过载保护：限流、熔断、本地缓存托底。
- 实例挂了要有降级，不要无限重试 DB。

**卡点**

- 击穿 ≠ 大 key：击穿是热点过期；大 key 是体积。
- 穿透的空值 TTL 太长会挡住刚插入的合法数据。

## 3. 生产坑 / 反例

- **只背名字对不上号**：面试官举「活动商品库存 key 到期」那是击穿。
- **Redis 挂了还没命中限流**：雪崩的最大杀伤是实例不可用。
- **互斥锁没有过期**：回源线程挂了，热点一直锁死。

## 4. 60 秒口述

> 穿透是查没有的数据打穿 DB，用空值和布隆挡。击穿是单个热 key 过期，用互斥回源或逻辑过期。雪崩是大批 key 同时失效或 Redis 挂，TTL 随机加高可用加限流。  
> 三者都是缓存没托住流量，但病根不同，对策不能混用。
