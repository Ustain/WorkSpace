# 37. 布隆过滤器能防什么、误判怎么办 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **穿透防护**。用很少内存判断「一定不存在 / 可能存在」。

- **一定不在**：可以直接拒绝，不打 DB。
- **可能在**：还要查缓存和 DB（假阳性）。

它 **不能** 100% 防穿透，也 **不擅长删除**。

## 2. 核心机制

- 一个大 bit 数组 + 多个哈希。加入元素时把对应 bit 置 1。
- 查询：有一个 bit 为 0 → 一定不存在；全为 1 → 可能存在（哈希碰撞）。
- 误判率由数组大小、哈希个数、元素数量决定。元素越塞越满，误判越高。

Redis 侧常用 RedisBloom 模块，或自己用 bitmap（能力弱一些）。

**和空值缓存比**

- 空值：精确，但每个非法 id 一个 key，占内存、可被刷爆。
- 布隆：内存固定，适合「海量不存在 id」。

**卡点**

- 假阳性：多打一次 DB，可接受。
- 假阴性：布隆说没有但 DB 有 → 业务少数据。正常布隆不会假阴，除非删 bit 或没更新就查。
- 删除：不能随便把 bit 置 0，会伤到别人。要用计数布隆或重建。

## 3. 生产坑 / 反例

- **DB 新增了，布隆没加** → 假阴，用户查不到。写入路径必须同步 add。
- **承诺零误判** → 错答。
- **用布隆当权限系统** → 误判会放过不该放过的（看场景；存在性挡穿透 OK，授权不行）。

## 4. 60 秒口述

> 布隆用来挡缓存穿透：说没有就一定没有，可以不打 DB；说有只是可能有，还要回源。有误判没有漏判（在正确维护的前提下）。  
> 删除不友好，新数据必须写入时加入。误判靠调大数组，不能吹 100%。
