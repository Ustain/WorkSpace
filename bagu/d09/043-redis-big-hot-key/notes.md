# 43. 大 key / 热 key · 口试

## 1. 属于哪块？和相邻方案差在哪？

必须拆开：

- **大 key**：单个 key 体积大或成员极多（几 MB 的 string、几十万 field 的 hash）。
- **热 key**：访问 QPS 集中在极少数 key，体积可以很小。

一个 key 可以又大又热，但对策不同。

## 2. 核心机制

**大 key 危害**

- GET/DEL/HGETALL 在主线程跑很久，阻塞。
- 集群迁槽、主从全量、AOF rewrite 更痛。
- 网络出口被一条回复占满。

**热 key 危害**

- 打满单核/单槽/单分片。
- 击穿时 DB 单行被打爆。

**发现**

- `redis-cli --bigkeys` / `--hotkeys`（有额外开销）。
- 监控：client-output-buffer、单命令耗时、热点统计。

**治理大 key**

- 拆：hash 按 field 分片成多个 key；list 按时间分桶。
- 删除用 `UNLINK`（异步）而不是 `DEL`。
- 禁止 HGETALL，改游标 `HSCAN`。

**治理热 key**

- 本地缓存（Caffeine）挡一层。
- 复制成多个副本 key 随机读。
- 读写分离 + 本地。
- 业务拆热点（库存分桶）。

## 3. 生产坑 / 反例

- **把热 key 当大 key 只拆体积**：QPS 仍打一点。
- **DEL 大 key 当常规运维**：主线程卡死。
- **监控平均值**：热点在 P99 和单分片 CPU 上。

## 4. 60 秒口述

> 大 key 是体积或成员多，命令和复制都会堵主线程，要拆 key、SCAN、UNLINK。热 key 是访问集中，要本地缓存、多副本随机读、业务分桶。  
> 两者经常一起出现，但一个拆数据，一个摊流量，别混。
