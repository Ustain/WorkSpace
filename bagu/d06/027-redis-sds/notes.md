# 27. SDS 为什么不用 C 字符串 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **Redis 字符串底层 SDS（Simple Dynamic String）**。C 字符串是 `\0` 结尾的 char*；SDS 自带长度、分配信息和灵活二进制。

## 2. 核心机制

C 字符串的问题：

- 求长要 `strlen` 扫到 `\0`，O(n)。
- 不能存中间 `\0` 的二进制（图片、protobuf）。
- 拼接容易缓冲区溢出，或每次都 realloc。
- 修改可能频繁分配。

SDS 怎么解：

- 头里存 **len**、**alloc**（或不同 SDS 头档位），`STRLEN` O(1)。
- 仍在末尾放 `\0` 以便兼容部分 C 函数，但 **以 len 为准**，中间可含 `\0`。
- 空间预分配：不太大时成倍扩，很大时定额扩，减少 realloc。
- 惰性释放：缩短后不立刻还内存，留给下次写。

不同长度用 `sdshdr8/16/32/64`，小字符串头更短。

**卡点**

- 预分配让 SDS 占用 > 逻辑长度，这是用内存换 CPU。
- embstr 把 RedisObject 和 SDS 一次分配，短字符串更省；改长会变成 raw。

## 3. 生产坑 / 反例

- **把 Redis string 当 C string 截断**：二进制安全，别用 `\0` 当结束。
- **超大 string 当 blob**：单 key 几十 MB，GET/DEL 阻塞（大 key）。

## 4. 60 秒口述

> Redis 不用裸 C 字符串，用 SDS：自带长度 O(1)，二进制安全，预分配减少 realloc。C 字符串怕 `\0`、怕溢出、求长要扫。  
> 短字符串还能和对象头一起分配。坑是预分配多占内存，以及单 string 太大变成大 key。
