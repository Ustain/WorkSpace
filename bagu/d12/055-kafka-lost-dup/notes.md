# 55. 消息丢失 vs 重复怎么防 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **端到端可靠性对照**。先问丢在哪一段：生产、Broker、消费。

默认语义是 **至少一次**（开重试、手动提交成功后）。少一次会丢，多一次要幂等。

## 2. 核心机制

**防丢（生产+集群）**

- acks=all，`min.insync.replicas>=2`。
- 关闭 unclean 选举。
- 生产者失败要重试，不能吞异常当成功。
- 同步发送或回调确认后再告诉上游成功。
- Broker 刷盘：`acks=all` 等 ISR，仍依赖副本磁盘。

**防丢（消费）**

- 处理成功再交 offset，不要自动提交。
- 处理失败不要跳位点，除非进死信并记录。

**防重复**

- 生产：幂等 Producer。
- 消费：业务唯一键、状态机、去重表。
- 需要 Kafka 内部 EOS 再开事务。

**对照一句话**

- 防丢：确认机制往后推（等到副本、等到业务成功）。
- 防重：重试不可避免，所以 **幂等**。

## 3. 生产坑 / 反例

- **只调 acks 不管消费提交** → 仍丢。
- **只做消费幂等不管 acks=0** → 仍丢。
- **用「全局 HashSet 去重」当幂等** → 重启失效、内存爆。

## 4. 60 秒口述

> 丢消息看三段：生产没等到 ISR、Broker 副本不够、消费先交 offset。重复来自重试和至少一次，用幂等生产和业务去重。  
> 可靠链路是 acks=all + min.isr + 手动提交 + 幂等。精确一次是加码，不是默认。
