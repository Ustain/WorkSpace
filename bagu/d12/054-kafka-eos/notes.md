# 54. 精确一次与事务消息 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **Kafka EOS（Exactly-Once Semantics）**。它保证的是 **Kafka 内部链路**：生产重试不重复、消费-转换-再生产这条读改写不丢不重。

**不等于** 业务 DB 只落一次。落库仍要幂等（题 89）。

## 2. 核心机制

EOS 三件套：

1. **幂等 Producer**（PID+序号）。
2. **事务**：`transactional.id`，一批写多个分区要么全可见要么都不可见。
3. **read_committed**：消费者不读未提交事务消息。

典型 **consume-transform-produce**：

- 消费、写输出 Topic、把消费 offset 写进同一事务提交。
- 失败整笔 abort，不会出现「输出写了位点没交」或反过来。

**卡点**

- 事务有延迟和吞吐代价。
- 消费者要 `isolation.level=read_committed`。
- 和外部 MySQL 不是一个事务（除非自己做事务消息/本地表）。

## 3. 生产坑 / 反例

- **面试说「开了 EOS 业务就不会重复」**——错答。
- **所有 Topic 开事务**：监控、日志类不值得。
- **事务没关 unclean 选举 / acks 太弱**：EOS 前提仍是可靠副本。

## 4. 60 秒口述

> Kafka 精确一次是幂等生产加事务，保证 Kafka 链路上不丢不重，消费位点可以和输出写在一个事务里。  
> 它不管你 insert 订单表。业务精确一次还是要幂等键。EOS 有成本，不是每个 Topic 都开。
