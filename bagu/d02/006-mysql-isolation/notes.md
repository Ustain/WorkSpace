# 6. 四种隔离级别与三种读异常 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **事务并发控制**：多个事务同时读写时，允许出现哪些「读到的数据和预期不一致」。

- **隔离级别**：在 **一致性** 和 **性能** 之间折中，级别越低并发越好、异常越多。
- InnoDB 默认 **RR（可重复读）**；Oracle/SQL Server 默认常是 RC。

三种读异常（ANSI SQL 定义）：

| 异常 | 现象 |
|------|------|
| **脏读 Dirty Read** | 读到别的事务 **未提交** 的数据 |
| **不可重复读 Non-repeatable Read** | 同一事务内 **两次读同一行，结果不同**（别的事务 **提交** 了修改） |
| **幻读 Phantom Read** | 同一事务内 **两次范围读，行数/集合不同**（别的事务 **插入/删除** 了满足条件的行） |

## 2. 核心机制：四级对照表（必背）

| 隔离级别 | 英文 | 脏读 | 不可重复读 | 幻读 |
|----------|------|:----:|:----------:|:----:|
| 读未提交 | READ UNCOMMITTED | ✓ | ✓ | ✓ |
| 读已提交 | READ COMMITTED | ✗ | ✓ | ✓ |
| 可重复读 | REPEATABLE READ | ✗ | ✗ | ✓* |
| 串行化 | SERIALIZABLE | ✗ | ✗ | ✗ |

\* **InnoDB 在 RR 下用 MVCC + 当前读锁，快照读幻读被抑制；当前读仍可能幻读**（题 8 细讲）。标准 RR 定义上幻读仍可能发生，MySQL 是加强版。

**各级一句话**

- **RU**：几乎不隔离，能读未提交 → 生产不用。
- **RC**：每次 SELECT 拿 **新快照** → 同事务内同一行可能两次不同（不可重复读）。
- **RR**：同事务 **第一次读** 建立 Read View，之后快照读 repeatable → InnoDB 默认。
- **Serializable**：读加锁，读写互斥 → 最稳最慢，很少默认用。

**怎么设置**

```sql
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
-- 或全局、或在 my.cnf: transaction-isolation = READ-COMMITTED
```

## 3. 生产坑 / 反例

- **RC vs RR 选哪个**：MySQL 默认 RR；不少互联网改 **RC**（更少 gap 锁、死锁少，语义接近 Oracle）。不是谁绝对更好，看业务和锁容忍度。
- **把 RR 说成「完全没有幻读」**——只对 **快照读** 成立；`SELECT ... FOR UPDATE` 仍可能遇到（题 8）。
- **脏读和不可重复读混淆**：脏读 = 未提交；不可重复读 = 已提交的修改。
- **幻读和不可重复读混淆**：不可重复读是 **同一行** 变了；幻读是 **多出来/少了行**（范围）。

## 4. 60 秒口述

> 事务隔离级别从低到高：RU、RC、RR、Serializable。三种读异常：脏读读未提交；不可重复读同事务两次读同一行不同；幻读两次范围读行集不同。  
> 对照表：RU 三种都有；RC 无脏读；RR 无脏读和不可重复读；Serializable 都没有。InnoDB 默认 RR，快照读用 MVCC；RR 下幻读要分快照读和当前读。生产常见 RC 与 RR 权衡，别背 RR 绝对无幻读。
