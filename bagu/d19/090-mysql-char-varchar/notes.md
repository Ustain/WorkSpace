# 90. CHAR vs VARCHAR · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **定长 vs 变长字符串列**。InnoDB 行格式下差别没有老教材那么玄学，但面试仍要说对。

## 2. 核心机制

- **CHAR(n)**：定长（字符数），短了补空格（比较时可能忽略尾空格，看 SQL 模式）。
- **VARCHAR(n)**：变长，额外 1～2 字节存长度，长数据才占满。

**怎么选**

- 真定长且很短（MD5、国家码）可用 CHAR。
- 大多数名字、地址、URL 用 VARCHAR。
- n 是 **字符数** 不是字节；utf8mb4 下 CHAR(10) 最坏 40 字节。

**和索引、行溢出**

- 过长 VARCHAR 可能溢出到页外（off-page）。
- 长度声明过大：不是立刻占满磁盘，但临时表、排序、最大行长计算会按上限估计。

## 3. 生产坑 / 反例

- **CHAR 存变长名字**：浪费且空格语义坑。
- **VARCHAR(1) vs CHAR(1)** 纠结没意义，看团队规范。
- **CHAR 比较尾空格** 导致唯一约束意外相等。

## 4. 60 秒口述

> CHAR 定长补空格，VARCHAR 变长带长度头。几乎所有业务字符串用 VARCHAR；固定短码可以用 CHAR。utf8mb4 按下字符计长度。别把 VARCHAR(255) 当不占空间的无限大，声明过长仍影响最大行和临时表。
