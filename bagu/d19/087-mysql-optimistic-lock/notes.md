# 87. 乐观锁 vs 悲观锁 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **并发改同一行怎么互斥**。

- **悲观**：先锁再改（`SELECT FOR UPDATE`），认为冲突多。
- **乐观**：带版本号/CAS 更新，`UPDATE ... WHERE id=? AND version=?`，认为冲突少。

## 2. 核心机制

**悲观**

- 事务里当前读加行锁，别人写等待。
- 冲突高（库存秒杀要慎用长事务悲观）、死锁风险。

**乐观**

```sql
UPDATE t SET stock=stock-1, version=version+1
WHERE id=? AND version=? AND stock>=1;
```

影响 0 行就重试。无长事务持锁。

**和 MVCC**

- MVCC 解决读；写冲突仍要锁或 CAS。乐观锁常建立在版本列上。

## 3. 生产坑 / 反例

- **秒杀只乐观不限流**：重试风暴打爆 DB。热点还要库存分桶、队列。
- **悲观事务里调远程**：锁持有时间爆炸。
- **version 不用唯一条件**：ABA 或漏防。

## 4. 60 秒口述

> 悲观是 FOR UPDATE 先锁再改，适合冲突多、要强互斥。乐观是版本号 CAS，失败重试，适合冲突少。  
> 写路径都要防丢更新。秒杀不能只靠乐观锁重试，要削峰。
