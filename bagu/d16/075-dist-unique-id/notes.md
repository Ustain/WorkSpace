# 75. 分布式 ID · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **分库分表后主键怎么唯一且最好趋势递增**（B+ 友好）。

## 2. 核心机制（对比说）

| 方案 | 优点 | 坑 |
|------|------|-----|
| UUID | 简单 | 无序，InnoDB 页分裂，索引膨胀 |
| DB 号段 | 递增、可控 | 单点、要高可用 |
| Redis INCR | 快 | 持久化/切换可能回退或跳号 |
| 雪花 Snowflake | 趋势递增、本地生成 | 时钟回拨；机器 id 要管 |
| 美团 Leaf 等 | 号段+雪花工程化 | 仍要部署 |

**雪花结构直觉**：时间戳 + 机器 + 序列号。同一毫秒同一机器靠序列。

**卡点**

- 时钟回拨：拒绝发号或等，或用逻辑时钟。
- 机器 id 冲突：两个节点同一 workerId → 撞号。
- 趋势递增不是绝对单调（不同机器时间差）。

## 3. 生产坑 / 反例

- **UUID 当聚簇主键**：写入随机打页。
- **雪花当安全 token**：可推测时间与机器。
- **多机房不加 IDC 位**：时间回拨和时钟同步更痛。

## 4. 60 秒口述

> 分片后用雪花或号段，图趋势递增保护 InnoDB。UUID 简单但随机写裂页。Redis/DB 发号要考虑高可用和跳号。  
> 雪花怕时钟回拨和 workerId 冲突。选能讲清这几个坑的方案就行。
