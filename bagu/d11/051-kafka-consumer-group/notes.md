# 51. 消费组与 offset · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **谁消费、进度记在哪**。

- **消费组 Group**：同一 `group.id` 共同消费一个 Topic，分区在组内均分。
- 不同组互不影响，各自有一份 offset → 广播用不同组，分担用同一组。

offset 是 **组 + 分区** 的进度，现在存在内部 Topic `__consumer_offsets`。

## 2. 核心机制

- 组内：一个分区同一时刻只分配给一个消费者。
- 消费者数 > 分区数：多出来的空闲。
- 消费者数 < 分区数：有人拿多个分区。

**offset 语义**

- 下一次该从哪条开始拉。提交了才算「组已处理到这」。
- 未提交就挂：再均衡后可能重复消费。
- 先提交后处理失败：可能丢失（题 53）。

**reset**

- 没有位点：`auto.offset.reset` 的 earliest/latest。只影响 **无位点或越界**，不是每次启动。

## 3. 生产坑 / 反例

- **两个服务共用一个 group.id**：抢分区，互相饿死。
- **用组来做广播还共用 id** → 变成负载分担。
- **把 offset 当业务主键** → 不够，业务要自己幂等表。

## 4. 60 秒口述

> 同一消费组分担分区，一个分区组内只能一个人拿；不同组独立位点，相当于广播。offset 记组在每个分区处理到哪，存在内部 topic。  
> 消费者别超过分区数。位点提交时机决定重复还是丢失。group.id 千万别乱共用。
