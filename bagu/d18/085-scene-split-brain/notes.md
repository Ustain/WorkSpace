# 85. Redis / ZK 脑裂 · 口试

## 1. 现象

两边都以为自己是主：双写、数据分叉、切回后覆盖丢失。ZK 分区则可能一边只读/不可写。

## 2. 止血

- **立刻只保留一个写入口**：摘掉分区里的旧主、禁写、或断网络一侧。
- Redis：确认哨兵客观下线和新主，旧主 `SLAVEOF` 新主前先停写。
- 对账：双写窗口的数据要日志/binlog 比对。

## 3. 定位

- 网络分区、哨兵不足 3、`min-replicas-to-write` 未开。
- ZK：2 节点或跨机房分区导致过半失败。
- 客户端缓存了旧主地址。

## 4. 根治

- 哨兵/etcd 奇数、跨故障域；写要最少副本。
- 客户端只信哨兵/域名。
- 强一致场景用 ZK/etcd 锁或 DB，不靠 Redis 主从。
- 定期演练分区。

## 5. 60 秒口述

> 脑裂是两边都能写。止血是只留一个主、堵住旧主，再对账。Redis 异步复制切主容易丢，要 min-replicas 和奇数哨兵。ZK 过半写入，分区时宁可不可用也不双主。
