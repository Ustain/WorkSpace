# 82. 线上死锁 · 口试

## 1. 现象

报 `1213 Deadlock`，部分事务回滚，接口失败率升。可能伴随锁等待升高。不是所有超时都是死锁。

## 2. 止血

- 失败请求 **按业务重试**（幂等前提下）。
- 若死锁风暴：限流该写接口，避免越重试越锁。
- 不要把 `lock_wait_timeout` 调到很大当修复。

## 3. 定位

- `SHOW ENGINE INNODB STATUS` 最近死锁：两条 SQL、索引、行锁还是 gap。
- 是否 RR 间隙、是否加锁顺序相反、是否缺索引锁太多行。

## 4. 根治

- 统一按主键顺序更新；缩短事务；能一条 UPDATE 就不先 SELECT。
- 补索引；评估 RC 减 gap。
- 业务重试带抖动。

## 5. 60 秒口述

> 死锁会回滚一方，应用要幂等重试。止血是限流加有节制重试。定位 INNODB STATUS 看两条 SQL 和锁类型。根治统一加锁顺序、缩事务、补索引。调大超时没用。
