# 84. 既要顺序又要并行 · 口试

## 1. 现象

业务要同订单有序，又要整体吞吐。单分区太慢；乱分区又乱序。

## 2. 止血

- 先保正确：热点订单临时单线程，吞吐降级可接受。
- 积压时不要随便加分区打散老 key。

## 3. 定位

- 顺序边界：全局、用户、订单？
- 是否同 key 被多线程消费、是否扩过分区、是否重试插队。

## 4. 根治

- **有序粒度 = key 粒度**：订单 id 当 key，分区内单线程处理该分区。
- 并行靠 **很多 key 分散到很多分区**。
- 不同域不要挤同一 key。
- 失败策略：要保序就停分区重试；否则破坏顺序换吞吐。

## 5. 60 秒口述

> 顺序只能分区内，并行靠更多分区和更多 key。同订单用同一 key，组内一分区分给一个消费者且单线程处理。全局有序只能单分区。扩分区会改 hash，要提前规划。
