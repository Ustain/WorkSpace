# 46. Broker / Topic / Partition / Replica · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **Kafka 数据模型**。并行和顺序的单位是 **分区**，不是 Topic。

## 2. 核心机制

- **Broker**：Kafka 进程/节点，存分区日志。
- **Topic**：逻辑主题，下面切成多个 **Partition**。
- **Partition**：有序、追加写的日志；**同一分区内有序**，分区之间无序。
- **Replica**：分区的副本。其中一个 **leader** 读写，其余 **follower** 拉数据。ISR 是跟上的副本集合（题 47）。

**生产者** 把消息打到某分区（按 key 哈希或轮询）。  
**消费者组** 里，一个分区同一时刻只给组内一个消费者（题 51）。

**卡点**

- 吞吐靠加分区；顺序靠同 key 同分区。
- 分区数不是越多越好：文件句柄、选举、rebalance 成本都涨。

## 3. 生产坑 / 反例

- **Topic 单分区还说要水平扩展消费**——并行度 ≤ 分区数。
- **所有消息不设 key 又要顺序**——做不到全局顺序。
- **副本=1**：broker 挂就丢。

## 4. 60 秒口述

> Topic 是逻辑名，真正存的是分区日志。分区内有序可并行，副本有 leader 和 follower。生产按 key 进分区，消费组内一分区分给一个消费者。  
> 要吞吐加分区，要顺序固定 key。Broker 只是存这些分区的机器。
