# 48. 为什么快：顺序写、零拷贝、页缓存 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **Kafka 吞吐为什么能到磁盘量级还很快**。不是「全在内存像 Redis」。

三件套：**顺序追加写日志**、**OS 页缓存**、**零拷贝发给消费者**。

## 2. 核心机制

**顺序写**

- 分区日志只 append，不改中间。磁盘顺序写接近顺序带宽。
- 和数据库随机改页完全不同。

**页缓存**

- 数据几乎不经过 JVM 堆，靠 OS page cache。
- 热数据读内存，冷数据读盘仍是顺序。
- JVM GC 压力小。

**零拷贝**

- 传统：盘 → 内核 → 用户态 → 内核 socket。
- `sendfile`：页缓存直接到网卡，少两次拷贝、少上下文。
- 消费者拉取大批量时特别划算。

**还有**

- 批量、压缩、分区并行。
- 顺序读消费。

**卡点**

- 机械盘随机 IO 多了（太多分区、刷盘策略差）优势就没了。
- 零拷贝对 SSL/压缩场景会打折，需要解密/解压时走用户态。

## 3. 生产坑 / 反例

- **分区极多**：变成很多小文件随机刷。
- **堆内缓存消息**：失去页缓存设计。
- **把快理解成不落盘**：acks=all 仍要副本落日志。

## 4. 60 秒口述

> Kafka 快是因为分区日志顺序追加，用 OS 页缓存而不是堆，发送用零拷贝从页缓存到网卡。再加上批量压缩和分区并行。  
> 它快的是吞吐路径，不是单条延迟一定比内存队列低。分区过多或每次都加密压缩，零拷贝和顺序写的优势会下降。
