# 44. Pipeline、事务、Lua 区别 · 口试

## 1. 属于哪块？和相邻方案差在哪？

都属于 **少 RTT / 组合操作**，保证强度完全不同。

| | 减 RTT | 原子执行 | 失败回滚 |
|--|:------:|:--------:|:--------:|
| Pipeline | ✓ | ✗ 只是打包发送 | ✗ |
| MULTI/EXEC 事务 | 有 | 排队后一起执行，中间不被插队 | **不回滚**（语法错全取消，运行时错继续） |
| Lua | ✓ | 脚本期间独占主线程 | 脚本自己逻辑 |

## 2. 核心机制

**Pipeline**

- 客户端一次发多条命令，再一次收多条回复。
- 服务器仍一条条执行，中间可以夹别人的命令（看连接）。
- 适合批量 GET，没有事务语义。

**事务 MULTI/EXEC**

- 命令入队，EXEC 时连续执行。
- **不是回滚事务**：`EXEC` 里某条失败，其他照样成功。
- `WATCH` 乐观锁：被改则 EXEC 失败。
- Cluster 要求 keys 同槽。

**Lua**

- `EVAL` 在主线程一次跑完，中间无其他命令。
- 用来做「读+条件+写」真正原子（锁释放、库存扣减）。
- 脚本不能太慢，否则全局阻塞。

**卡点**

- 把 MULTI 说成和 MySQL 事务一样能回滚 → 错。
- Pipeline 不保证原子。

## 3. 生产坑 / 反例

- **Lua 里访问大 key 或循环过多**：卡死 Redis。
- **事务里用 DISCARD 当业务回滚**：只取消队列，已 EXEC 的不能靠它撤销。
- **跨槽 Pipeline 还以为是一次原子**。

## 4. 60 秒口述

> Pipeline 只是打包减 RTT，不原子。MULTI/EXEC 保证排队命令连续执行，但运行时错误不回滚。真正原子用 Lua，脚本要短。  
> 扣库存、释放锁这种读后写用 Lua；批量读用 Pipeline。别把 Redis 事务当成 InnoDB。
