# 77. 线上慢 SQL 怎么查 · 口试

场景题按 **现象 → 止血 → 定位 → 根治**，先活过来再讲 B+。

## 1. 现象

接口 RT 升高、线程池打满、CPU 或 IO 打满、告警慢查询条数涨。用户侧超时。先确认是 **某一条 SQL** 还是实例级（锁、IO、磁盘满）。

## 2. 止血（5 分钟内）

- 限流、降级非核心查询、切读到健康从库或只读缓存。
- 若是一条坏 SQL 打满：杀掉执行中的会话（`KILL`），临时把该接口下线或挡流量。
- 磁盘满 / 连接打满先腾连接、扩连接要谨慎。

## 3. 定位

- 慢日志、`processlist`、performance_schema、监控里的 p99。
- `EXPLAIN` / `EXPLAIN ANALYZE`：type、key、rows、Extra。
- 是全表扫、回表过多、filesort、锁等待还是统计信息错。
- 是否刚发版、是否缺索引、是否隐式转换、是否深分页。

## 4. 根治

- 改 SQL / 加联合与覆盖索引 / ANALYZE TABLE。
- N+1 改批量；深分页改游标。
- 仍不够再缓存、归档、分库分表。
- 防下次：慢查询门禁、Explain 进 CR、限流。

## 5. 60 秒口述

> 先看是单 SQL 还是整库挂。止血：限流降级，必要时杀会话。定位慢日志加 Explain，分清扫表、回表、排序还是锁。根治改写法补索引，最后才分表。不要一上来分库。
