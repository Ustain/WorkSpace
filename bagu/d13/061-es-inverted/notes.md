# 61. 倒排索引 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **ES/Lucene 为什么全文检索快**。正排是 doc → 字段；倒排是 **term → 哪些 doc**。

和 MySQL B+ 比：B+ 擅长等值/范围/排序；倒排擅长「词出现在哪」，不擅长强事务。

## 2. 核心机制

1. 文档分析：分词、小写、过滤停用词 → 得到 term。
2. 词典（term dictionary）：term 有序列表，能二分/FST 查到。
3. 倒排表（posting list）：该 term 的文档 id 列表，常加频率、位置（短语查询）。
4. 查询：把 query 分词，取 posting 做交/并，再打分排序。

**text vs keyword**（题 67）

- text 走分析器，倒排的是 token。
- keyword 整串一个 term，精确过滤、聚合。

**卡点**

- 倒排不存行事务；更新是删旧加新（不可变 segment）。
- 不分词的 id 查询不该用 text。

## 3. 生产坑 / 反例

- **用 ES 当 MySQL**：要关联更新、强一致、复杂事务会痛。
- **中文没配分词器**：查不到预期词。
- **把倒排说成哈希**——还有有序词典和压缩 posting。

## 4. 60 秒口述

> 倒排是词到文档列表。写入时分词，查的时候拿 posting 做交并再打分。所以全文搜比扫全表快。  
> 和 B+ 树分工不同：ES 管检索，MySQL 管事务。text 分词，精确匹配要用 keyword。
