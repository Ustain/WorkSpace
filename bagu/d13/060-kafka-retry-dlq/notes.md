# 60. 重试、死信、延迟消息 · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **消费失败怎么办**。Kafka 原生不像 RocketMQ 那样内置延时等级和死信队列，要 **应用自己做** 或用框架。

## 2. 核心机制

**重试**

- 瞬时错误：本地重试几次（注意挡住 poll → rebalance）。
- 仍失败：发到 **retry topic**（可带 backoff），原消息提交位点，避免卡住分区。
- 无限重试会堵死分区，后面消息全停——**要不要堵取决于要不要严格顺序**。

**死信 DLQ**

- 超过最大次数进死信 Topic，告警、人工/任务修复。
- 死信要有原 Topic、分区、offset、异常、业务键。

**延迟消息**

- Kafka 无一等公民延迟队列。常见：时间轮 + 内部 Topic、pause 分区、用 RocketMQ/延时组件。
- 用 zset 做延时再投 Kafka 也可以。

**卡点**

- 同分区要顺序：失败就不能跳，只能停或写「占位失败」语义。
- 不要顺序：失败转发 retry topic，主链路继续。

## 3. 生产坑 / 反例

- **catch 异常后提交 offset 又不记死信** → 丢。
- **失败就抛、不提交**：正确保序，但 Lag 一直在，要告警。
- **重试 Topic 和主 Topic 同组** → 乱。

## 4. 60 秒口述

> Kafka 失败策略要自己设计：要顺序就停在当前 offset 重试；要吞吐就把失败转到重试 Topic，多次后进死信。  
> 延迟消息 Kafka 不内置，用独立延时组件或换 RocketMQ。无论哪种，失败不能既吞异常又往前交位点。
