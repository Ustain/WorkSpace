# 59. Kafka vs RocketMQ vs RabbitMQ · 口试

## 1. 属于哪块？和相邻方案差在哪？

属于 **MQ 选型**。用四个维度说：模型、吞吐、功能、运维。结尾给选型句。

## 2. 核心机制（嘴里一张表）

| 维度 | Kafka | RocketMQ | RabbitMQ |
|------|-------|----------|----------|
| 模型 | 日志/分区 | 队列+队列级消费，事务/延迟强 | 交换机路由，灵活 |
| 吞吐 | 最高，顺序写 | 高 | 相对低 |
| 顺序 | 分区内 | 队列/顺序消息 | 有限 |
| 事务/延迟消息 | 弱于 RMQ（Kafka 事务是链路 EOS） | 事务消息、延时/定时成熟 | 插件延迟，事务有但重 |
| 积压 | 为积压设计 | 能扛 | 积压时内存/性能差 |
| 运维 | 分区规划、ISR | 相对顺手 | 简单小规模香 |

**选型一句**

- 日志收集、大数据、超高吞吐、允许分区顺序 → **Kafka**。
- 电商订单、要事务消息、延时关单、业务队列语义 → **RocketMQ**。
- 复杂路由、任务派发、规模不大 → **RabbitMQ**。

## 3. 生产坑 / 反例

- **用 RabbitMQ 扛亿级日志** → 积压打跪。
- **用 Kafka 硬做复杂 delay 和事务消息** → 能做但不顺手。
- **三个都要「功能最全」** → 没有，按主需求。

## 4. 60 秒口述

> Kafka 是分布式日志，吞吐和积压最强，顺序在分区内。RocketMQ 更像业务消息中间件，事务消息和延迟消息好用。RabbitMQ 路由灵活，适合中小规模。  
> 要吞吐选 Kafka，要事务和延迟选 RocketMQ，要简单路由选 Rabbit。
