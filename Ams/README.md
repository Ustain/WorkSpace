# IT 资产管理系统 · AMS

面向科研机构 / 事业单位的 IT 办公设备资产管理系统。覆盖笔记本、台式机、显示器、鼠标、键盘、转接头、投影仪等设备的**全生命周期管理**：入库登记 → 领用申请 → 审批 → 到期提醒 → 归还 / 续借 → 报修 → 报废，每一步都留痕可追溯。

整个系统编译为**一个可执行文件**：前端页面、SQLite 数据库驱动、演示数据全部内嵌，不依赖外部数据库，也不需要 Node 构建环境。

---

## 快速开始

```bash
cd WorkSpace/Ams
go run .            # 或 ./run.sh    Windows: run.bat
```

浏览器打开 <http://localhost:8080>。首次启动会自动建库并灌入一套完整演示数据（194 台设备、12 个用户、6 个部门、30 条申请、若干报修工单）。

### 主动补充的功能

- **资产履历时间轴**：每台设备的入库、领用、归还、续借、报修、调拨、信息变更都有独立记录，变更内容精确到「品牌：Dell → Lenovo」这种字段级描述。
- **资产标签二维码**：为每台设备生成二维码，打印后贴在机身，现场盘点扫码即可跳转到该设备。
- **续借与归还流程**：续借在**原到期日基础上顺延**而非从今天重算，避免用户通过提前续借变相延长占用。
- **报修工单**：用户报修后设备自动转入「维修中」并从可领用池摘出；管理员处理完可选择退还原领用人或收回库房。
- **批量操作**：批量报废 / 转维修 / 回库 / 调拨 / 删除，领用中的设备会被自动跳过并在结果里列出。
- **操作审计日志**：记录所有写操作的执行人、时间、入参、来源 IP，**密码类字段自动脱敏**。
- **邮件记录与预览**：未配置 SMTP 时邮件进入「模拟投递」，内容照常落库，可在系统内查看完整 HTML 渲染效果 —— 演示环境不用真实邮箱也能展示完整通知链路。
- **手动触发到期扫描**：系统设置里一键执行，演示时不必等定时器。
- **资产管理员角色**：介于管理员与普通用户之间的第三种角色，用来展示 RBAC 的实际区分度。
- **可配置提醒策略**：提前提醒天数、单次最长借用天数、邮件开关均可在线调整，立即生效。
- **消息中心与未读角标**：站内信按类型分类，侧边栏与顶栏红点自动轮询刷新。
- **数据看板下钻**：点击首页卡片（如「已逾期 22 台」）直接跳到设备台账并带上对应筛选条件。
- **设备类型可配置**：类型编码用于生成资产编号（`NB-2026-0001`），默认借用天数会作为申请表单初始值。
- **离线可用**：Vue / Element Plus / ECharts 全部本地化内嵌，断网环境照常运行。

## 技术方案

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Go 1.24 + Gin | 分层：`api`（HTTP）→ `service`（业务）→ `model`/`store`（数据） |
| 数据库 | SQLite（`glebarez/sqlite` 纯 Go 驱动） | 无需 CGO、无需外部数据库，`go build` 出来就能跑 |
| ORM | GORM | 开启 WAL 提升并发读 |
| 鉴权 | JWT + bcrypt | 每次请求回查用户，禁用账号 / 调权限立即生效 |
| 权限 | 权限点（Permission Code）RBAC | 角色持有权限点集合，前端菜单按同一份权限点渲染 |
| 前端 | Vue 3 + Element Plus + ECharts | **免构建**：全局版 CDN 产物本地化，无 npm / Vite |
| 导入导出 | excelize + encoding/csv | — |

## 几个设计上的取舍

**申请阶段不改设备状态。** 提交领用申请时只做可行性校验，真正变更状态发生在审批通过的数据库事务里。否则「申请了一堆但都没批」会把设备占死。审批通过时会**二次校验**设备状态，挡住两人同时申请同一台设备造成的超领。

**提醒去重靠字段打标，不靠定时器精度。** `assets.reminded_at` / `overdue_at` 两个标记保证临期与逾期对每台设备各只推一次；归还或续借时清空标记，下一个借用周期能重新提醒。这样即使扫描任务跑得再频繁，用户也不会被重复打扰。

**管理员和普通用户的通知通道不同。** 管理员只收站内信，而且是聚合摘要（「12 台临期、22 台逾期」）而非每台一条；普通用户收站内信 + 邮件。审批类消息对管理员是高频事件，全推邮件会把邮箱淹掉。

**关联字段用 0 表示「无」而不是 NULL。** 设备未被领用时 `holder_id = 0`。这与物理外键约束互斥，因此建表时关掉了外键，引用完整性放在业务层保证（删除用户前检查其名下设备、删除类型前检查其下设备等）。

**月度趋势在 Go 里聚合。** SQLite 的 `strftime` 解析带时区的时间串不稳定，与其和存储格式较劲，不如把几百条记录拉回来在 Go 里按月分桶。数据量级决定了这不是瓶颈。

**列表只放台账核对必需的字段。** 品牌型号、存放位置、规格配置都收进详情抽屉。设备表有 17 个字段，全铺进表格只会撑出横向滚动条，反而让「到期时间」这种关键列被挤到视野外。

## 配置项

全部通过环境变量覆盖，均有合理默认值：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AMS_ADDR` | `:8080` | 监听地址 |
| `AMS_DB` | `data/ams.db` | SQLite 文件路径 |
| `AMS_JWT_SECRET` | `ams-demo-secret-change-me` | **生产环境务必修改** |
| `AMS_TOKEN_TTL_HOURS` | `12` | 登录态有效期 |
| `AMS_REMINDER_INTERVAL_MINUTES` | `30` | 到期扫描周期 |
| `AMS_SMTP_HOST` / `PORT` / `USER` / `PASS` / `FROM` | 空 | 留空则邮件进入模拟投递模式 |

开启真实发信：

```bash
AMS_SMTP_HOST=smtp.example.com AMS_SMTP_PORT=465 \
AMS_SMTP_USER=noreply@example.com AMS_SMTP_PASS=****** \
AMS_SMTP_FROM=noreply@example.com go run .
```

## 演示动线建议

1. **登录页** 点「系统管理员」卡片一键登录。
2. **统计看板** —— 8 个指标卡 + 6 张图表；点「已逾期 22 台」直接下钻到台账。
3. **设备台账** —— 试试多选状态 + 到期时间区间；点设备名看**资产履历时间轴**和**二维码标签**；导出一份 Excel。
4. **系统设置** —— 点「立即执行一次扫描」，弹窗显示本次临期 / 逾期 / 推送条数。
5. **邮件记录** —— 查看刚才生成的提醒邮件，点「查看正文」看渲染效果。
6. 退出，用 `zhouheng` 登录 —— **菜单完全不同**，只剩个人工作台。
7. **可领用设备** → 申请一台设备 → **我的申请** 看到待审批。
8. 切回 `admin` → **审批中心** 通过该申请。
9. 再切回 `zhouheng` → **消息中心** 收到审批通过通知，**我的设备** 里多了这台设备。
